## ЛР0 — Підготовча робота

Розгортання середовища розробки та повторення основ роботи з реляційними базами даних.

**Що зроблено:** PostgreSQL 17 піднято в Docker-контейнері замість локальної інсталяції: конфігурація описана у `docker-compose.yml`, тож базу можна відтворити однією командою. Створено схему з двох пов'язаних таблиць, наповнено її даними та написано Python-код, що виконує вибірку, зміну й видалення записів.

**Схема БД**

`employees` — співробітники: `id`, `name`, `position`.
`tasks` — завдання: `id`, `title`, `status`, `employee_id`.

Зв'язок: `tasks.employee_id → employees.id` з правилом `ON DELETE SET NULL`, тому після видалення співробітника його завдання залишаються в базі без відповідального.
Поле `status` обмежене через `CHECK` значеннями «В процесі» та «Зроблено».

**Файли**

| Файл | Призначення |
|---|---|
| `docker-compose.yml` | конфігурація контейнера PostgreSQL 17 |
| `check_db.py` | перевірка підключення до БД з Python |
| `create_tables.py` | створення схеми (перезапускається безпечно) |
| `seed.sql` | наповнення таблиць даними |
| `queries.py` | SELECT з JOIN, UPDATE, DELETE |

**Запуск**

```bash
cd lab0
docker compose up -d
python check_db.py
python create_tables.py
docker exec -i lab0-postgres psql -U postgres -d lab0 < seed.sql
python queries.py
```

## ЛР1 — Зберігання та доступ до даних для аналітики

Порівняння рядкового (CSV) і стовпчастого (Parquet) форматів зберігання за розміром файлу та швидкістю аналітичних запитів.

**Дані:** [PaySim](https://www.kaggle.com/datasets/ealaxi/paysim1) з Kaggle: 6 362 620 синтетичних фінансових транзакцій, 11 стовпців, 471 МБ у CSV. Файл не входить до репозиторію через розмір, його потрібно завантажити окремо.

**Результати**

Розмір файлу:

| Формат | Розмір |
|---|---|
| CSV | 470,7 МБ |
| Parquet без стиснення | 407,8 МБ | 
| Parquet + snappy | 257,1 МБ | 

Час виконання запитів (найкращий з трьох запусків):

| Запит | CSV | Parquet + snappy | Прискорення |
|---|---|---|---|
| Читання всього файлу | 9,30 с | 4,59 с | ~2x |
| Підрахунок за 1 стовпцем | 2,60 с | 0,02 с | ~130x |
| Групування за 2 стовпцями | 3,40 с | 0,64 с | ~5x |
| Фільтр + сортування, 3 стовпці | 5,40 с | 2,70 с | ~2x |

**Висновок:** Виграш Parquet тим більший, чим меншу частку стовпців потребує запит: стовпчастий формат зчитує з диска лише потрібні стовпці, тоді як рядковий CSV доводиться розбирати повністю. Стиснення snappy зменшує файл ще на третину і практично не впливає на швидкість читання, сповільнюючи лише запис.

**Файли**

| Файл | Призначення |
|---|---|
| `convert.py` | перетворення CSV -> Parquet, порівняння розмірів |
| `benchmark.py` | вимірювання часу однакових запитів до обох форматів |

**Запуск**

```bash
cd lab1
# покласти transactions.csv (PaySim) у цю папку
pip install pandas pyarrow
python convert.py
python benchmark.py
```
